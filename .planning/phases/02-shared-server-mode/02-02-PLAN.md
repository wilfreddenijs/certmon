# User And Role Administration

## Objective

Close the role-management UAT gap by exposing the already-defined CertMon roles through a secure administrator workflow. Keep authorization server-side, revoke sessions after security-sensitive account changes, and include the two authentication usability fixes recorded during UAT.

## Artifacts this phase produces

- `certmon.db.Database.list_users()`
- `certmon.db.Database.update_user_identity_and_roles()`
- `certmon.db.Database.set_user_disabled()`
- `certmon.db.Database.set_user_password_hash()`
- `certmon.db.Database.delete_sessions_for_user()`
- `certmon.db.Database.count_enabled_admins()`
- `certmon.auth.SUPPORTED_ROLES`
- `certmon.auth.AuthService.create_user()`
- `certmon.auth.AuthService.update_user()`
- `certmon.auth.AuthService.set_user_enabled()`

- Administration tab user-management UI

<threat_model>
ASVS level: 1
Blocking threshold: high

- High: privilege escalation through arbitrary role strings. Mitigation: validate every submitted role against `SUPPORTED_ROLES`; reject empty or unknown role sets with HTTP 400 before persistence.
- High: loss of all administrative access. Mitigation: database-backed final-enabled-admin checks must block disabling an account or removing its `admin` role when it is the last enabled administrator.
- High: continued access after disable or password reset. Mitigation: delete all sessions belonging to the target user in the same transaction as the account mutation.
- High: password disclosure in logs or API responses. Mitigation: accept plaintext only at the password endpoint, hash immediately, return `public_user()` data only, and never include passwords or hashes in audit details.
- Medium: cross-site account mutation. Mitigation: all mutating `/api/users` routes remain behind the existing authenticated CSRF middleware.
</threat_model>

## Success Criteria

- An administrator can complete the full user lifecycle through the UI.
- Viewer and operator accounts can be created through normal application workflows and exhibit their server-enforced permissions.
- Security-sensitive account changes revoke sessions and are auditable without secrets.
- Login works with Enter and first-admin setup rejects mismatched password confirmation.
