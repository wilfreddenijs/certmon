# Full Server Backup And Staged Recovery

## Objective

Expose the existing `BackupService` through a safe operator workflow. Produce a portable encrypted package, verify uploaded packages before writing a restored installation into a new directory, and require an explicit offline directory switch instead of replacing live data in process.

## Artifacts this phase produces

- `certmon.permissions.Permission.MANAGE_SERVER_BACKUP`
- `certmon.config.RuntimeConfig.max_backup_upload_bytes`
- `certmon.server_backup.ServerBackupPackageError`
- `certmon.server_backup.ServerBackupPackageResult`
- `certmon.server_backup.StagedRestoreResult`
- `certmon.server_backup.ServerBackupPackageService`
- `ServerBackupPackageService.export_package()`
- `ServerBackupPackageService.stage_restore()`
- `POST /api/server-backup/export`
- `POST /api/server-backup/restore`
- Versioned `certmon-server-backup-<backup_id>.zip` format
- Administration tab Server backup section
- `tests/test_server_backup_api.py`
- `tests/test_server_backup_package.py`

<threat_model>
ASVS level: 1
Blocking threshold: high

- High: extraction path traversal or archive bomb. Mitigation: reject absolute paths, `..` components, links, duplicate members, unexpected top-level files, more than 10,000 members, and more than 2 GiB total uncompressed content before extraction.
- High: overwrite or corruption of the live installation. Mitigation: derive a new sibling staging directory, reject any existing destination, call `BackupService.restore_backup()`, and never rename or delete `CERTMON_DATA_DIR` from the running web process.
- High: unauthorized bulk secret export. Mitigation: introduce `MANAGE_SERVER_BACKUP`, grant it only to `security_admin` and `admin`, authorize before parsing passphrases or uploaded archives, and retain CSRF enforcement.
- High: restored vault remains bound to the source Windows account. Mitigation: include a passphrase-encrypted recovery package and call `Vault.restore_recovery_package()` with the current installation's protector inside the staged restore directory before declaring it ready.
- High: plaintext secret leakage. Mitigation: package only encrypted artifact files and the passphrase-encrypted recovery package; never decrypt certificate or device secrets during export; redact passphrases and file contents from logs and audit events.
- Medium: denial of service through large uploads or expensive key derivation. Mitigation: enforce request and archive size limits and return stable 400/413 responses.
</threat_model>

Return backup ID, final staged path, creation timestamp, and a fixed list of offline activation instructions. The final path must be a new sibling such as `<active-name>-restore-<backup-id>` and must never equal or reside inside the active data directory.

Keep `BackupService` as the source of truth for SQLite online backup, HMAC verification, file hashes, and representative-key checks; do not duplicate those checks in the wrapper.

Add `Permission.MANAGE_SERVER_BACKUP`; grant it to `security_admin` and implicitly to `admin` through `LOCAL_PERMISSIONS`, but not to viewer, operator, or ca_admin. Instantiate `ServerBackupPackageService` with the configured data directory, database, vault, runtime key protector, and artifact mutation lock.

Add `POST /api/server-backup/export`, accepting JSON `passphrase`, authorizing `MANAGE_SERVER_BACKUP` before reading it, and returning `certmon-server-backup-<backup_id>.zip` as an attachment. Generate the response from a temporary file outside the active data directory and register response-close cleanup so the temporary ZIP is deleted after transfer or on error. Add `POST /api/server-backup/restore`, accepting multipart fields `backup` and `passphrase`, authorizing before reading either field, enforcing `max_backup_upload_bytes` while streaming to a temporary file rather than trusting only `Content-Length`, and returning JSON with `backup_id`, `staged_path`, and explicit activation steps. Map package validation errors to 400, upload-size failures to 413, conflicts such as an existing target to 409, and unexpected failures to a redacted 500 response. Delete temporary upload files on every outcome.

Audit `server_backup_exported`, `server_backup_export_failed`, `server_restore_staged`, and `server_restore_failed`. Include backup ID and non-secret outcome metadata only; never include passphrases, archive contents, recovery-package contents, or cryptographic key identifiers. Preserve the existing `/api/ca/backup/*` routes unchanged as the separate Local CA-only workflow.

## Success Criteria

- An authorized administrator can download a portable full server backup from the Administration tab.
- A valid package can be uploaded and fully verified into a new, inactive sibling directory.
- The restored installation retains authentication, Local CA, certificates, encrypted artifacts, metadata, and audit history.
- The running installation is never overwritten or switched by the web process.
- Full server backup remains distinct from Local CA-only export/import.
