<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Session/database -> `/api/auth/status` -> browser | Server-derived effective permissions cross into untrusted client code for presentation decisions. |
| Browser -> Flask routes | Users can bypass hidden controls and call routes directly; backend authorization remains mandatory. |
| Artifact store -> public catalog/download | Public metadata and bytes must be separated from private keys and combined PEMs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-02-06-01 | Elevation of Privilege | Client visibility and mutation routes | high | mitigate | Tasks 06-01/06-02 retain `authorize()` as the boundary, add checks to inventoried mutation gaps, and use UI hiding only as usability defense-in-depth. |
| T-02-06-02 | Information Disclosure | `/api/certificates/public` | high | mitigate | Task 06-01 allowlists safe fields and four public names, probes only `read_public()`, and independently tests private names/content are absent. |
| T-02-06-03 | Tampering | Role/permission interpretation | high | mitigate | Server computes the additive union with `permissions_for_roles()`; JavaScript consumes permission strings and contains no duplicate role map. |
| T-02-06-04 | Information Disclosure | Dynamic controls and unauthorized loaders | high | mitigate | Task 06-02 hides restricted generated controls and proves Viewer makes no restricted startup/tab requests. |
| T-02-06-05 | Denial of Service | 401 recovery loop | medium | mitigate | Task 06-03 uses a one-flight guard, excludes auth endpoints, cancels active timers, and never replays the failed request. |
| T-02-06-06 | Spoofing | Stale browser after revocation | high | mitigate | Existing server session deletion is preserved; Task 06-03 treats the next protected 401 as authoritative and clears the browser principal state. |
</threat_model>
